## Milestone Execution Rules

- The developer owns the project roadmap.
- Never independently change the milestone sequence.
- Implement only the currently assigned milestone.
- Do not start future milestones without approval.
- Preserve existing architectural decisions.
- Do not refactor unrelated code.
- Identify breaking changes before implementing them.
- Run relevant tests after every implementation.
- Report completion with test results and modified files.
- After every milestone, create a Word file (`doc/milestones/milestone-<n>.docx`)
  explaining what was done in that stage: goal, what was built, files,
  architecture decisions, tests and results, limitations, and anything that
  changed later. Commit it with the milestone.
- Wait for developer approval before continuing.
